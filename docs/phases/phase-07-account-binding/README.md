# Phase 7 — Привязка аккаунта

> **Статус:** не реализовано. Заглушка после MVP «логин только по имени» (Phase 6 UX).

## Цель

Дать пользователю способ **привязать / восстановить** аккаунт на другом устройстве или после потери локальных credentials: явный ввод пароля (или иной механизм привязки), без смены модели «имя = уникальный аккаунт».

## Зависимости

- [Phase 6 — gRPC API](../phase-06-api-integration/README.md) — `Auth.Login`, EncryptedSharedPreferences / Keystore
- Контракт сервера: [03-accounts-db](../../../server/docs/03-accounts-db.md)

## Контекст (текущий MVP)

- На LoginScreen запрашивается **только имя**.
- Свободное имя → регистрация; сервер выдаёт пароль один раз → клиент сохраняет в Keystore, UI пароль **не показывает**.
- Занятое имя без пароля на устройстве → ошибка «Имя занято, введите другое имя».
- Повторный вход на том же устройстве: пароль подставляется из Keystore при совпадении username.
- В онлайн-лобби имя **только для чтения** (username аккаунта).

Без Phase 7 нельзя войти в уже существующий аккаунт на новом устройстве / после очистки данных приложения.

## Задачи (черновик)

- [ ] UI ввода / подтверждения пароля (или flow привязки) на Login / отдельном экране
- [ ] Повторный Login с паролем при «имя занято» или явном «У меня уже есть аккаунт»
- [ ] Документация UX и обновление api-contracts
- [ ] Unit-тесты ViewModel + маппинг ошибок Unauthenticated
